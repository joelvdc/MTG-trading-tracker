# Developing MTG Trader: the hands-on notes

For any assistant (Claude Code, Cline, …) or person working on this repository. The working agreement is
`AGENTS.md` / `CLAUDE.md`; this file holds the practical facts and gotchas learned along the way.

## The two parts
- `app/`: the Android app (Kotlin, Jetpack Compose, Room). Package `com.mtgtrader`.
- `web/`: the website at https://mtgtrader.vercel.app (Next.js, Vercel, Neon Postgres). It edits the app's sync file
  as one more device. Details: `web/README.md`.

## Building on the owner's PC (Windows)
- JDK 18: `JAVA_HOME="C:\Program Files\Java\jdk-18.0.2"` (Git Bash: `export JAVA_HOME="/c/Program Files/Java/jdk-18.0.2"`).
  The JDK on PATH is too new for this Gradle.
- Android SDK: `%USERPROFILE%\Android\sdk` (platform 35, build-tools 35). adb: `...\sdk\platform-tools\adb.exe`.
- The build folder is `%LOCALAPPDATA%\mtgtrader-build` (kept out of OneDrive; the root `build.gradle.kts` derives it
  from `LOCALAPPDATA`). A second copy of the code needs its own `LOCALAPPDATA`, e.g.
  `LOCALAPPDATA='C:\Users\JC\AppData\Local\mtg-rel' ./gradlew assembleRelease`.
- VS Code's Java extension runs Gradle in the same build folder and can lock files ("Failed to delete …"): close VS
  Code or build with another `LOCALAPPDATA` as above. A stale `generated/ksp/...` folder (DAO methods missing) is fixed
  by deleting it.
- Node 22 for `web/`: on this PC it is in `%LOCALAPPDATA%\nodejs` (Git Bash: `export PATH="$LOCALAPPDATA/nodejs:$PATH"`).
- GitHub CLI `gh` is signed in as joelvdc.
- Memory: the PC has 24 GB. Gradle (~4–5 GB) plus the emulator (~3.5 GB) slows it down badly. Never run both at once;
  run `./gradlew --stop` after a build.
- Paths contain spaces (`OneDrive - Aqvila\0 Personal\...`): always quote them.
- Never edit files with PowerShell `Get-Content | Set-Content`: it garbles ·, é, —, €. Use an editor tool or Python with
  UTF-8. Before a release, search the `.kt` files for `Â`, `â€` or `Ã` (signs of garbled text).

## Checks
- App, everything: `./gradlew testDebugUnitTest verifyRoborazziDebug assembleDebug` (`assembleRelease` on the PC
  before a local release). Run it once and wait; don't poll or loop it.
- Screenshot tests (Roborazzi, `app/src/test/screenshots/`): after an approved visual change run
  `./gradlew recordRoborazziDebug`, then keep only the pictures that really changed
  (`git checkout -- app/src/test/screenshots/` for the rest; recording rewrites every picture with invisible
  differences). They run in UTC with English formats, so pictures pass on GitHub's Linux machines and on the PC.
- Website: in `web/`, `npm test` and `npm run typecheck` (there is no lint set up).
- GitHub's **Tests** check runs the app checks on every pull request; it doesn't run the website tests, so run those
  yourself.

## Things that must change together
- **Database version** (`data/Database.kt`): every bump needs a `MIGRATION_x_y` whose SQL matches the exported schema
  in `app/schemas/` (generated by the build: commit the new JSON), and the new migration added to the `addMigrations(...)`
  lists in the `Release*Test` files that build a database.
- **Sync format** (`Sync.FORMAT` in `data/Sync.kt`): raise it when a synced field is added that an older app would
  lose. Phones on older versions then pause syncing until they update, so ask the owner first. In the same release:
  `WEB_FORMAT` in `web/src/lib/syncfile.ts`, the website code for the field, the tests that assert the number, and
  the shared sample files:
  1. `WRITE_WEB_FIXTURES=1 ./gradlew testDebugUnitTest --tests '*WebSyncFixtureTest*'` (writes `web/test/fixtures/app-sync.json`)
  2. `WRITE_WEB_FIXTURES=1 npm test` in `web/` (writes `web-edited-sync.json`)
  3. Run both test suites again without the variable.
- **Outside services** (Scryfall, Cardmarket, Archidekt, Commander Salt, …) or new synced fields: update
  `docs/health-check-instructions.txt` (the weekly health check reads it from `main`).
- Scryfall rejects the default OkHttp User-Agent: every request sends `MTGTraderAndroid/1.0`.
- Deck ids: an Archidekt deck's id in the app is its Archidekt id (`Deck.archidektId`, also the games' `deckId`);
  local decks have negative ids.

## Releases
Two routes, both in `AGENTS.md` → Releases:
- **Pull request + GitHub Actions** (any assistant, any machine, also cloud sessions): branch, pull request, wait for
  the Tests check to pass, merge, then Actions → **Release** → Run workflow on `main`. GitHub signs with its stored
  secrets; nobody needs the keystore.
- **Local on the PC** (Claude Code only): uses the keystore in `keystore/`. Other assistants never use or open it.
After either route: the published APK must carry the same certificate as the previous release
(`apksigner verify --print-certs`, compare the SHA-256; currently `f79e1ce9…93f5`).

## Website notes
- Website-only changes need no app release: once on `main`, Vercel deploys `web/` by itself. Check
  https://mtgtrader.vercel.app/api/health afterwards (`ok: true`, `syncFormat` equal to the app's).
- Local look-check without the owner's login: in `web/`, `DATABASE_URL=memory` plus any random `SESSION_SECRET`, then
  `npx next dev -p 3123`; a temporary `src/app/api/devseed/route.ts` can seed the memory store from
  `test/fixtures/app-sync.json` and log the browser in. Delete it afterwards, and undo the `web/AGENTS.md` and
  `tsconfig.json` changes `next dev` makes. Browser POSTs need the header `X-Requested-With: mtgtrader`.
- Never contact the owner's Nextcloud (cloud.nocar.me): it blocks requests from outside Denmark, which is expected.
- Never print or change Vercel's secrets (`SESSION_SECRET`, `NEXTCLOUD_PASS`, `CRON_SECRET`) or the owner's Cloudflare
  rules without asking.

## Emulator (optional)
- AVD `mtgtest` (Pixel 6, Android 15). It holds a release build, so install release APKs (a debug build clashes on
  signature). Boot it only when Gradle isn't running (see Memory above).
- Git Bash needs `MSYS_NO_PATHCONV=1` for adb device paths. If screenshots come back frozen or blank, restart it with
  `-gpu swiftshader_indirect`.
